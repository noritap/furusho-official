# FURUSHO OFFICIAL｜Photo Library Workflow v1.0

Status: PROPOSED / DRAFT PR only
Scope: `noritap/furusho-official` public website assets

## Purpose

Separate *private original photo preservation* from *public website distribution*. Keep one verified home for originals, minimize duplicated photos and avoid publishing unapproved images.

## Storage ownership

1. **Private Google Drive: `FURUSHO_PHOTO_MASTER/`**
   - Holds all submitted originals, unchanged.
   - Categorized under `01_PROFILE`, `02_PERFORMANCE`, `03_LESSON`, `04_STUDIO`, `05_CAREER_ARCHIVE`, and `99_REVIEW_REQUIRED`.
   - Private master manifest and rights/selection review are maintained there. Do **not** copy the private manifest, Drive identifiers, or unapproved files to this public repository.
   - Drive is *not* an image CDN; do not grant link-wide permissions to serve unapproved originals.

2. **Public GitHub Pages: `noritap/furusho-official`**
   - Holds *only reviewed and approved* lightweight photos actually required for the public website.
   - Current published assets remain in place. New assets should use `assets/images/` and descriptive, ASCII-only file names.
   - Existing `assets/data/media-assets.json` is the website's visual asset inventory generated by `tools/collect_visual_assets.py`; do not introduce a second competing public Source of Truth.
   - `docs/PHOTO_REUSE_AUTHORIZATION_NOTE.md` remains the canonical permission note for reusing images already published on approved owner-operated sites, within its stated scope. This does not grant blanket clearance for newly submitted originals.

3. **ChatGPT Sites UX Lab**
   - Used for non-public design tests of permitted imagery, layout/cropping/alt text and responsive variants.
   - Not a second production photo master. A successful prototype does not prove legal clearance for public hosting.
   - Never use third-party performer, audience or student photos in an accessible site preview when permission for that exposure is unknown.

## Publication gate (mandatory)

For each candidate:
1. Identify exact original via Google Drive path and recorded SHA-256.
2. Verify photographer rights, subject/participant consent as applicable, venue/production restrictions, third-party brand context, and intended web use.
3. Explicitly record `PUBLIC_APPROVED` in the *private* original manifest. Default is `REVIEW_REQUIRED` and public upload is prohibited.
4. Create an optimized *copy* with EXIF/GPS metadata removed. Preserve the original.
5. Prefer a 1200–1800 px appropriate master WebP copy (adjust to actual display density and quality); use a separate responsive variant only when materially useful.
6. Use appropriate alt text and explicit `width`/`height` or aspect ratio to reduce layout shift.
7. Avoid the same photo twice on one page and repeated near-identical large photos from one session.
8. Distinguish teaching photos, live performance, current activities and historical work. Do not imply third-party endorsement or a performance credit not supported by evidence.

## Implementation / review

- Add any approved files on a feature branch; never silently update `main`.
- Update referencing HTML/CSS as needed, regenerate/validate existing visual asset registry using repo tools and CI checks.
- Check HOME, Profile, Projects, Career and Media links/visuals at 320, 390, 768 and 1440 px.
- Review image requests, cropping/focal points, relative paths, accessibility, and page load before PR merge.
- Keep Sites design changes and GitHub production work as separate, clearly reviewed changes.
- Publish **no new photos** under this PR; this PR establishes only a documented process.

- 32 originals have been catalogued in the private owner Drive master.
- All new originals remain `REVIEW_REQUIRED`; no blanket rights grant is inferred from receipt in chat.
- No original images or private master manifest are added to this public repository.
- Website public assets and current page behavior are unchanged by this workflow-only proposal.
